# 安全 HTTPS 服务连接设计

## 单一端点规则

建立一个不可变 `ServiceEndpoint` 值对象作为服务地址唯一解析入口。它只接受语法有效、带主机且 scheme 为 `https` 的 URI，规范化 API base URL 与图片 URL；原始用户输入、规范值和验证错误分开表达。网络、登录、同步、附件和图片代码不得各自拼接或重新校验 host。

兼容性只对 `https://me.xiqi.site/` 承诺；其他地址即使通过 TLS 校验也不因此获得 API 兼容承诺。不得把目标 host 硬编码成绕过通用安全校验的特例。

## TLS 边界

- 使用平台默认信任管理器与主机名验证器。
- 删除 trust-all `TrustManager`、恒真 `HostnameVerifier` 和所有明文 HTTP fallback。
- 重定向后的每一跳继续要求 HTTPS；不得从 HTTPS 降级到 HTTP。
- 登录、同步、附件上传下载、目标服务图片和任何独立 Retrofit/OkHttp 客户端共用同一配置工厂。
- 错误按地址无效、证书不受信、证书过期、主机名不匹配、网络不可达、认证失败和服务错误分类，但不输出凭据或正文。

## 已保存账户失效状态

当账号保存的端点后来不再满足 TLS 要求时，账户进入 `secure-endpoint-required` 状态。其本地 Room 数据仍可浏览、编辑和导出，所有远程请求在网络边界前失败；用户在单独的修复流程中输入新地址，只有一次真实 TLS/API 验证成功后才原子替换原配置并解除阻断。失败不改写旧配置。

## 测试策略

使用本地受控 TLS 测试服务器覆盖有效证书、不受信 CA、过期证书、主机名不匹配、HTTP 与降级重定向；使用目标服务完成有效 HTTPS 冒烟。静态扫描保证不存在自定义宽松信任实现，并对所有网络入口做结构性覆盖检查。

## 回滚

安全策略不得回滚到明文或跳过证书校验。若新端点解析或错误 UX 有缺陷，只能回滚 UI/解析改动并保持网络默认拒绝；本地数据和原端点配置始终保留。
