# 安全的 HTTPS 服务连接

## 目标

确保所有 Leanote 服务连接只使用系统信任、证书有效且主机名匹配的 HTTPS，不再以兼容性名义暴露凭据和笔记数据。

## 来源与当前证据

- 来源：`docs/adr/0006-require-valid-https-for-custom-services.md`。
- `app/src/main/java/org/houxg/leamonax/network/ApiProvider.java:39-118` 当前信任任意证书、跳过主机名校验，并直接接受未限定协议的服务地址。

## 需求

- Leanote 服务地址必须使用 HTTPS。
- TLS 连接必须由平台默认信任链验证有效证书，并验证请求主机名。
- 不提供信任任意证书、关闭主机名验证、生产环境明文 HTTP 或失败后降级连接的开关和 fallback。
- 无效服务地址、证书链、证书有效期和主机名错误必须产生可区分、可操作且不泄露敏感信息的失败。
- 日志不得记录令牌、密码、完整笔记内容或其他认证材料。
- 任何已保存账户的服务配置后来变为 HTTP、自签名证书、不受信证书、过期证书或主机名不匹配时，保留该账户的本地浏览、编辑和导出能力，但阻止登录、同步、附件传输、远程图片获取等全部网络操作。
- 受阻账户必须进入明确的安全配置修复状态；只有用户改为有效 HTTPS 地址并验证成功后才恢复网络能力。
- 不得自动改写服务 URL、删除账户或本地数据，也不得为已有账户临时启用 TLS 绕过。

## 验收条件

- [ ] 有效且主机名匹配的系统信任 HTTPS 服务可以连接。
- [ ] HTTP、自签名或不受信证书、过期证书、主机名不匹配均被拒绝，且没有静默降级。
- [ ] 网络实现不再包含 trust-all `TrustManager` 或恒真 `HostnameVerifier`。
- [ ] 登录、同步、附件上传下载和图片访问共用同一安全策略，未形成旁路。
- [ ] 错误界面可帮助用户修复服务配置，同时本地敏感数据不因网络失败被删除。
- [ ] 已保存账户的服务安全配置失效后仍可浏览、编辑和导出本地数据，但所有网络入口一致受阻。
- [ ] 修复流程只有在有效 HTTPS 验证成功后解除网络阻断；失败不会改写原服务配置。

## 范围外

- 应用内自定义 CA 仓库或“忽略证书错误”选项。
- 继续支持生产环境明文 HTTP 服务。

## 依赖

- 启动前要求 `09-09-android-platform-baseline` 完成；与 API 兼容任务共享服务地址与错误语义，但不依赖 UI 现代化。
