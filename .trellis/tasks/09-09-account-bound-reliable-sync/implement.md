# 账户绑定可靠同步实施计划

## 抽取同步核心

- [ ] 盘点所有同步入口、`Account.getCurrent()`、游标更新、冲突、附件和错误路径。
- [ ] 定义不可变 `SyncSessionContext` 与账户范围同步用例，让执行链显式接收上下文。
- [ ] 把页面生命周期操作迁移到结构化协程，保留明确取消和错误传播。

## 持久调度

- [ ] 由本任务在 Room 定义每账户单例的同步请求表、DAO、状态、请求代次、重试与租约字段；Room 基础任务不重复拥有该 Schema。
- [ ] 实现全局唯一 drain Worker，串行处理账户请求并在进程恢复时安全接管。
- [ ] 将活动请求的重复触发合并为同一账户请求；终态再次触发时事务性重置为新的 queued 代次；A 运行时 B 保持 queued，切换活动账户不影响 A。
- [ ] 确保 WorkManager Data、名称和日志不含令牌或其他凭据。

## 数据一致性

- [ ] 把每页数据应用与 USN 推进放入同一事务，覆盖拉取、推送、删除和冲突。
- [ ] 为创建/更新/附件操作建立可重试幂等身份与状态。
- [ ] 删除旧 `NoteSyncService` 启动入口和执行中读取全局账户的路径，不保留双调度。

## 验证

- [ ] 测试 A 同步中切换 B、B 排队、A 完成后 B 执行及两个账户数据/错误隔离。
- [ ] 测试活动请求重复触发、成功后再次触发、失败/取消后再次触发、网络失败、进程终止恢复、分页中断、附件部分失败和冲突。
- [ ] 对 `https://me.xiqi.site/` 执行受保护的临时数据同步验证。
- [ ] 运行 `.\gradlew.bat testDebugUnitTest`、`.\gradlew.bat connectedDebugAndroidTest`、`.\gradlew.bat lint`、`.\gradlew.bat assembleDebug` 和 `git diff --check`。

## 回滚点

- [ ] 同步核心、队列表、Worker、入口切换和旧 Service 删除分别形成审查点。
- [ ] 回滚前确认队列请求可迁移或明确保留；禁止直接清空队列制造成功状态。
