# 账户绑定可靠同步设计

## 不可变同步上下文

`SyncSessionContext` 在会话开始时一次性解析账户 ID、目标 `ServiceEndpoint`、凭据快照、数据库账户范围和各实体游标。同步引擎的所有方法显式接收该上下文；执行期间不调用 `Account.getCurrent()`，活动账户切换只影响新 UI 状态和后续排队请求。

WorkManager 的持久输入只包含稳定、非敏感的账户 ID 或队列请求 ID。Worker 启动后从 Room 读取账户记录并构造内存上下文；令牌不得进入 WorkManager Data、任务名、日志或异常文本。

## 全局串行队列

本任务在 Room 中拥有并定义同步请求队列表、DAO、状态机和租约。队列采用每账户单例行，并以账户 ID 唯一约束合并同一账户的活动请求。一个全局唯一的 `leanote-sync-drain` WorkManager 工作串行提取等待账户：A 运行时切换到 B，A 继续，B 的请求保留在队列；A 结束后才为 B 创建新的固定上下文。

队列状态显式为 queued、running、succeeded、failed 或 cancelled，并携带账户 ID、非敏感原因和重试信息。再次触发处于 succeeded、failed 或 cancelled 终态的账户时，同一事务把该单例行重置为 queued，清除旧租约与终态原因，并递增请求代次；不得把新请求误合并为已经完成。Worker 进程重启时把失去租约的 running 请求恢复为 queued；同一代请求通过幂等操作和游标事务避免重复应用。审计历史如有产品需求应另建历史表，不通过重复队列行隐式保存。

## 同步事务与幂等

- 拉取一页远程数据、应用本地变更和推进对应 USN 在同一账户事务中完成；数据写入失败不得推进游标。
- 推送使用稳定本地操作身份或服务端身份，使网络重试不会重复创建对象。
- 冲突处理复用 API 契约，不由调度器另行判断。
- 附件与笔记状态只有在远程确认后推进；部分失败保留可重试状态。
- 显式取消在安全检查点生效，不把部分页标为完成。

即时界面操作使用结构化协程并调用同一领域用例；需要离开界面继续的完整同步进入持久队列。两条入口共享账户范围、互斥与错误模型，不能实现两套同步引擎。

## 测试策略

使用可控假服务和 Room 测试数据库覆盖账户切换、重复排队、跨账户顺序、进程恢复、分页失败、游标事务、冲突和附件重试；目标服务测试只操作 API 任务资源账本内对象。

## 回滚

在切换入口前保留旧 Service；切换后删除旧启动路径和全局账户读取。禁止新旧调度器同时运行。回滚必须先停止并排空新队列，再切回前一完整实现，不能丢弃 queued/failed 请求。
