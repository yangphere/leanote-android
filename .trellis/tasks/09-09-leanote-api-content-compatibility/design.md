# Leanote API 与内容兼容设计

## 唯一服务契约

兼容性只由 `https://me.xiqi.site/` 当前部署的行为定义。客户端内部以类型化 DTO 与领域映射承载契约；固定夹具来自脱敏后的真实响应结构，不能包含令牌、账号、笔记正文或附件内容。其他 Leanote 版本、第三方分支和部署不进入测试矩阵。

## 双层验证

第一层为可离线复现的契约夹具，覆盖路径、参数、字段、错误、空值、分页、删除、冲突和附件响应。第二层为目标服务真实测试，用受保护环境变量注入账号与密码，验证 mock 无法证明的服务端 USN、冲突、附件和清理行为。

真实测试维护运行级资源账本：每个新建笔记本、笔记和附件立即登记服务端 ID；更新、冲突和删除只接收账本内 ID。同步返回的既有对象不进入断言、持久化输出或日志。清理按登记 ID 逆序执行，任何失败使测试失败并报告脱敏 ID。

## 内容不变量

- Markdown 源文本与 HTML 富文本分别是规范内容，不自动互转。
- `noteId`、USN、删除状态、脏标记、冲突副本和附件 ID 的含义不由客户端现代化改变。
- 错误必须保留可判别语义；解析失败、认证失败或服务错误不能返回空集合或成功结果。
- 日志和测试报告只保留路径、状态、错误类别、运行标记和脱敏对象 ID。

## 文件集合请求边界

`NoteService` 的单一文件集合编码器接收完成 prune 后的 `List<NoteFile>`，并始终写入 `FilesPresent=1`。它同时生成保留文件的 `Files[i][LocalFileId]`、`IsAttach`、`FileId`、`HasBody` 与需要发送正文的上传候选，避免 presence、元数据和二进制选择形成多个事实来源。

空列表表示“客户端提交了完整空集合”，因此只含 marker 而不伪造索引项；缺少 marker 才保留目标服务对历史客户端“文件集合未提交”的兼容语义。该编码器保持 package-private 且纯粹，数据库 prune/load 与 `MultipartBody.Part` 构造仍由服务层编排。新增和更新共用相同完整集合语义。

测试既直接断言空集合、保留远端文件和新本地文件的 wire 值，也验证真实保存路径在 prune/load 后调用该编码器，避免产生只被测试调用的虚假 seam。

## 下游接口

API 任务输出类型化契约、领域映射、文件集合请求编码器和测试夹具，供 Room、同步和编辑器任务消费。Room 不重复定义字段含义；同步不重复实现 USN/冲突判定；编辑器不重新解释 Markdown/HTML、附件身份或空集合 presence。

## 回滚

真实测试失败时先停止后续变更并尝试只清理账本对象。清理失败保留对象 ID 供人工处理，不扩大删除范围。客户端契约回滚必须连同 DTO、映射与夹具一起完成，避免测试和实现分叉。
