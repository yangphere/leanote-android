# Leanote API 与内容兼容

## 目标

在客户端现代化过程中保持既有 Leanote REST、USN 同步、冲突、内容格式和附件身份契约。

## 来源与当前证据

- 来源：`docs/adr/0003-preserve-data-and-api-contracts-during-migration.md`。
- `app/src/main/java/org/houxg/leamonax/network/api/` 当前定义登录、账户、笔记本、笔记、标签、附件等 REST 调用。
- `app/src/main/java/org/houxg/leamonax/service/NoteService.java:89-160,240-284` 当前实现 USN 分页和基于 `noteId/usn` 的冲突副本行为。
- `research/empty-files-marker-2026-09-13.md` 已确认：客户端删除最后一个图片或附件后不发送任何 `Files[...]` 字段，而目标服务用 `FilesPresent` / `HasFiles` 区分“完整空集合，清空全部资产”和“字段缺失，保持资产不变”。
- 唯一兼容目标是 `https://me.xiqi.site/` 当前部署所表达的 Leanote 服务契约；其他官方、自定义、历史或第三方 Leanote 服务端版本不在兼容承诺内。
- 已有专用测试账户可供验证，但账号与密码属于敏感配置，不写入仓库、任务文档、测试源码、命令行参数或日志。

## 需求

- 保持 `https://me.xiqi.site/` 当前部署所使用的 Leanote REST 路径、请求字段、响应字段、错误响应和身份认证语义。
- 保持 USN 分页、游标推进、删除、脏数据上传和冲突副本语义。
- Markdown 笔记以 Markdown 源文为规范内容，富文本笔记以 HTML 为规范内容；两者不得在迁移中相互转换或静默丢失。
- 保持图片与其他附件的身份、笔记关联和传输语义。
- 笔记保存必须把附件/图片关系编码为完整集合替换：无论集合是否为空都发送显式 `FilesPresent=1`（或目标服务等价 marker）；空集合不得用伪造 `Files[0]`、空字符串 ID 或省略字段表达。
- 文件集合 presence、索引元数据与二进制上传候选必须由同一请求编码边界生成；UI、DTO 和 Retrofit 声明不得各自复制空集合判断。
- 用固定契约夹具和 `https://me.xiqi.site/` 的真实服务验证客户端替换前后的等价行为。
- 真实服务测试凭据必须通过环境变量或受保护测试密钥注入；失败输出必须脱敏。
- 真实服务测试可以创建笔记本、笔记、冲突副本和附件，执行更新、同步与删除，但所有可变对象必须由本次运行新建、带唯一测试标记并登记服务端 ID。
- 测试不得主动选择、断言、修改或输出账号中的既有对象；同步接口不可避免地返回既有对象时，必须忽略其内容且不得写入测试产物或日志。
- 清理只能依据本次运行登记的服务端 ID 删除对象，不得按宽泛名称、时间范围或搜索结果批量删除；清理失败必须明确报告遗留 ID。

## 验收条件

- [ ] 现有 API 路径与字段具有可执行的请求/响应契约测试。
- [ ] 多页 USN、删除、离线修改、并发更新和冲突副本场景具有回归证据。
- [ ] 历史 Markdown、HTML、图片地址和附件样本往返后保持规范内容及身份。
- [ ] 删除最后一个内联图片或附件时，请求仍携带显式空文件集合 marker，目标服务删除所有对应资产并更新附件计数；省略 marker 的历史请求仍保持资产不变。
- [ ] 非空文件集合继续保留 `LocalFileId`、`FileId`、`IsAttach` 与 `HasBody` 身份，只有缺少服务端 ID 的条目进入二进制上传候选。
- [ ] 服务端错误不会被转换成成功、空数据或静默重试结果。
- [ ] 使用受保护凭据对 `https://me.xiqi.site/` 完成真实登录与目标 API 契约验证，证据不包含令牌、密码或笔记正文。
- [ ] 真实服务验证覆盖临时对象的创建、更新、USN 推进、冲突、附件和删除，并证明所有变更都限制在本次运行登记的 ID 集合内。
- [ ] 测试结束后已登记对象全部清理；若清理失败，验证结果明确失败并列出脱敏后的对象 ID，不伪报成功。

## 范围外

- 为现代化客户端发明不兼容的新服务端 API。
- 自动合并内容冲突。
- 兼容 `https://me.xiqi.site/` 之外的其他 Leanote 服务端版本、分支或部署。
- 通过伪造空文件记录或修改服务端历史兼容 fallback 来掩盖 Android 请求缺失 marker。

## 依赖

- 为 Room、同步和编辑器任务提供可执行契约基线。
- 启动前要求 `09-09-android-platform-baseline` 与 `09-09-secure-https-service-connections` 完成。真实服务基线和最终客户端回归都必须通过统一 HTTPS 边界连接，不允许为了提前采集夹具继续使用全信任 TLS。
